# Qobuz 10.2.0.0: штатний вхід через legacy API token — перевірка сумісності

## Висновок після аналізу DEX

Попередні TokenPanel v2, TokenLogin v3/v4 перевіряють `X-User-Auth-Token` і можуть завантажувати обране через `api.json/0.2`, але **не створюють штатної сесії Qobuz Android**.

Стандартна авторизація потребує:
1. `OAuthLoginDto`: профіль `UserDto` і `OAuthDto`.
2. `OAuthDto`: `tokenType`, `accessToken`, `refreshToken`, `expiresIn`.
3. `QWSAuthDto`: окремі `QWSAuthTokenDto` з JWT, endpoint і expiration.
4. Конвертації DTO → доменні `w2b`/`u2b` через `x2b`/`v2b`.
5. Запису в оригінальний менеджер `o9`, який зберігає OAuth у `kfd.e` та синхронізує профіль через `djg`.

Ці структури підтверджено розбіркою саме Qobuz 10.2.0.0 (versionCode 26110610).

## Перспективна серверна частина

Доступний виклик `POST /api.json/0.2/qws/createToken`, який за чинним авторизованим API-токеном може видати JWT для Qobuz Connect. Однак QWS JWT **не є** парою OAuth access/refresh токенів.

Для повноцінного входу потрібен підтримуваний сервером спосіб отримати/оновлювати OAuth-токени зі старого токена **або** штатний інтерактивний OAuth login (може містити CAPTCHA). Підтвердженого token→OAuth refresh grant для Qobuz 10.2.0.0 наразі немає.

## Безпечний критерій реалізації

**Не** вимикати перевірку сесії й не створювати фальшивий logged-in boolean. Таке втручання не забезпечить працюючі головний екран, бібліотеку й відтворення.

Реліз `Qobuz Token Native Login` можливий лише після перевірок:
- user_auth_token прийнятий Qobuz API;
- сервер видав справжні OAuth access/refresh токени для мобільного клієнта (чи іншу сумісну пару);
- `o9` підтвердив успішне збереження, профіль відновлюється після перезапуску;
- дійсно працюють головний інтерфейс, особиста бібліотека, запуск треку, пауза, відновлення та Hi-Res згідно з передплатою;
- оригінальний OAuth/CAPTCHA не пошкоджений.

## GitHub Actions

Скрипти `audit_native_auth.py`, `audit_session_bridge.py`, `audit_native_session_storage.py`, `audit_repository.py` збирають тільки технічні відомості про модель і точки виклику, без реальних токенів користувача. Вони не доводять коректність функціонального входу.

Поточні тестові APK — експериментальні, **не** native-token-login релізи.
